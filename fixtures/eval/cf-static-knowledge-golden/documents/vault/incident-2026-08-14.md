# Incident 2026-08-14 — Embedding Provider Outage

Severity: SEV-2. Duration: 47 minutes customer-facing impact.

## Timeline

09:12 UTC — Alerts fired: retrieval latency p95 above threshold, then
workspace availability probes failing.
09:18 UTC — Primary on-call identified the local embedding endpoint as
unreachable; workspaces reporting `unavailable`.
09:31 UTC — Confirmed the embedding container had exited on OOM. No source
data, index reference, or Qdrant collection was affected.
09:40 UTC — Container restarted with a raised memory limit; probes recovered.
09:59 UTC — All workspaces back to `available`; impact window closed.

## What held

The fail-closed behavior worked as designed. While the provider was down,
retrieval returned structured unavailable errors instead of guessing with a
different model. Because index identity (model/dimension) is recorded on the
active index, restart restored the exact provider and no reindex was needed.

## What did not hold

The availability probe timeout (2 seconds) produced a burst of false
`unavailable` reports during the container restart window, which slowed
triage. The container had no memory limit, so the OOM was a host event
without an in-container signal.

## Actions

Add a memory limit and a health-gated restart to the embedding container.
Increase the availability probe timeout to reduce restart-window flapping.
Document in the runbook that an `unavailable` workspace during a provider
restart is expected and needs no data action.
